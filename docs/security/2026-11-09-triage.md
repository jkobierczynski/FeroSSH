# Security review of 9 November 2026: what we found and fixed

On 9 November 2026 we received an AI-generated (ChatGPT) security review
of FeroSSH at commit `5f949f3`. The report is kept as received in
[2026-11-09-ai-review.md](2026-11-09-ai-review.md). Because no human
auditor wrote it, we took nothing in it as fact: we checked each finding
in our source and, for dependencies, in the published crate sources and
the upstream IronRDP issue tracker.

All findings below are fixed or decided in FeroSSH main since
9 November 2026 (pull requests #126 to #131). The first release that has
them is the one after v1.2.0.

## Findings

| ID | Report says | What we found | Fix |
|---|---|---|---|
| FSSH-01 | The built-in RDP viewer never checks the server's certificate | True in the code, but not reachable. The built-in viewer is only opened for a desktop on the SSH server itself (`localhost`), which the SSH host key already authenticates. RDP through a bastion (`Via`) goes to mstsc.exe, which checks the certificate itself. | #127 makes the localhost-only rule explicit: the viewer refuses any other host. |
| FSSH-02 | VNC is unencrypted between a bastion and another target; "None" is preferred over VNC authentication | Confirmed. | #128: the viewer prefers VNC authentication when the server offers it, says when a desktop has no password, and asks once before a VNC desktop whose last leg (bastion to target) is unencrypted. |
| FSSH-03 | IronRDP reassembles dynamic channel messages without a limit | Confirmed. `ironrdp-dvc` trusts the length a server announces (up to 4 GiB). Upstream issue [IronRDP#2092](https://github.com/Devolutions/IronRDP/issues/2092) is open; 0.10.0 is unchanged. The viewer's 1 GiB memory cap contained it to the desktop tab. | #129: the viewer checks each channel PDU before IronRDP sees it and ends the session when a dynamic channel message announces more than 1 MiB. |
| FSSH-04 | Desktop IPC queues are unbounded | Confirmed. If the viewer stalled, the window process (which has no memory cap) could grow. | #130: the window holds at most 4 MiB of queued desktop bytes and makes the network reader wait; the viewer's input queue holds 64 events. |
| FSSH-05 | `pageant 0.2.4` has an advisory | Partly. `0.2.5` adds a length check on requests FeroSSH writes to Pageant, which only matters with agent forwarding; FeroSSH has none. We found no published advisory. | #131 updates to `pageant 0.2.5` anyway. |
| FSSH-06 | IronRDP does not bound compressed static channel chunks | Confirmed in IronRDP ([IronRDP#2081](https://github.com/Devolutions/IronRDP/issues/2081), open; 0.10.0 unchanged). The viewer never asks for compression, but a server could still set the flag. | #129: compressed channel data ends the session, and a static channel message over 8 MiB too. |
| FSSH-07 | Desktop passwords show in `Debug` output and are copied into plain strings | Partly. Nothing logged them, and the viewer already wiped its own copies. | #131: desktop passwords travel in a type that prints as `Secret(..)` and is wiped on drop, and the IPC buffers that carry them are wiped too. One copy remains: IronRDP's `Credentials` takes a plain `String`. |
| FSSH-08 | Desktop clipboard sharing is on by default | True, by design at the time. | #126: the desktop and remote-app clipboard are now off until you turn them on. |

## Not checked

The report gives CVE numbers for the russh issues fixed in russh 0.65.1
(CVE-2026-116773 and CVE-2026-116774). We did not check those numbers.
FeroSSH has used russh 0.65.1 since PR #122.

## Possible later work

- VeNCrypt (TLS) for VNC, so the last leg through a bastion can be
  encrypted.
- Offering the reassembly limits to IronRDP upstream, then dropping the
  viewer's own checks once a fixed release is out.
