# FeroSSH v1.5.1

*Secure connections. Forged in Rust.*

FeroSSH 1.5.1 brings more of OpenSSH's everyday tools to FeroSSH: a Known hosts manager, host keys checked in DNS (SSHFP), host keys that follow a server's new keys (UpdateHostKeys), the `~.` and `~C` escape sequences, SOCKS on the server and Unix-socket forwards, tunnel-only connections, and `ssh://` links. It also adds font ligatures and fixes menus that could lose their names after a change of window colours. Two of these are on by default; see **Before you upgrade**. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) are the place to start.

## Before you upgrade

- **Host keys follow the server (`UpdateHostKeys yes`, as in OpenSSH).** After a login trusted through your `known_hosts`, a server may list all of its host keys. FeroSSH asks it to prove that it holds the keys you don't have yet, then adds them (hashed) and removes keys the server no longer lists. This happens only when that one file pinned the login, no other file has keys for the host, and every line for the host names that host alone. `@revoked` keys are never added, and the lines that stay are kept byte for byte. Set `UpdateHostKeys ask` in `~/.ssh/config` to see the changes without writing them, or `no` to turn it off.
- **Escape sequences are on.** In an SSH pane, `~` typed first on a line now starts an escape, as in OpenSSH: `~.` disconnects, and `~~` types a single `~`. Any other key after `~` sends both keys, so typing `~/` or `~user` works as before. Session > SSH escape sequences turns them off, and `EscapeChar none` turns them off for a host.

## Host keys

- **Known hosts manager.** Tools > Known hosts (Ctrl+Shift+K, or the lock in the tools rail) lists the keys in `known_hosts` and in every `UserKnownHostsFile` your ssh_config names. It shows the host, the kind of key (host key, `@cert-authority` or `@revoked`), the SHA-256 fingerprint and the file and line. Search by host name, and hashed `|1|` lines and wildcard lines that cover it are found too. Remove (Del) takes out whole lines after asking, twice for a revoked key. The file is changed only if every picked line is still exactly as listed, and the other lines keep their bytes and line endings. Copy fingerprint (Ctrl+C), Copy line and Reload (F5) are there too.
- **Host keys in DNS (SSHFP).** `VerifyHostKeyDNS yes|ask|no` in ssh_config looks up the host's SSHFP records, as OpenSSH does. With `yes`, a new key that matches a record in a DNSSEC-validated answer is trusted without a prompt. Otherwise the result is a line in the host key prompt, and a mismatch shows in red. `known_hosts` always wins: a pinned key still connects and a changed key is still refused. The lookup runs in the sandboxed worker. A DNSSEC answer is only as trustworthy as the way to your DNS server; the [guide](https://github.com/jkobierczynski/FeroSSH/blob/v1.5.1/docs/guide/everyday-use.md) explains.

## Connections and forwarding

- **Escape sequences.** In an SSH pane, or a tmux pane on one, `~` first on a line works as in OpenSSH:
  - `~.` disconnects;
  - `~C` opens an `ssh>` line for `-L`, `-R`, `-D` and `-KL`, `-KR`, `-KD`;
  - `~#` lists forwards and open connections;
  - `~R` asks for a new key exchange;
  - `~?` lists the escapes.

  Only keys you type count, so pastes, scripts and suggestions never start one. `EscapeChar` sets another character per host or for every host.
- **SOCKS on the server.** `RemoteForward 1080` with no target (or Server SOCKS (-R) in Tools > Port forwards) lets programs on the server reach, through SOCKS 4, 4a or 5, anything this PC can reach. This is OpenSSH's `-R port`.
- **Unix-socket forwards.** `-L` and `-R` take a socket path on either side, as in OpenSSH: forward a server socket such as a Docker or database socket to a port on this PC, or the other way round. A socket on this PC with a drive letter goes in brackets (`[C:\Users\me\db.sock]`); the form adds them.
- **Tunnel-only connections (`ssh -N`).** A connection of type *SSH tunnels only (no shell)*, `SessionType none` in ssh_config, or `-N` on the command line logs in, runs its port forwards and opens no shell. It reconnects when the connection drops and is never shared with other tabs, so closing them doesn't stop its forwards. `-L`, `-R` and `-D` now work on the command line too. PuTTY sessions set to "Don't start a shell or command at all" import as tunnel-only.
- **`ssh://` links.** `ssh://user@host:port` works at the connect prompt and on the command line. Settings > Open links can make Windows open `ssh://` and `sftp://` links with FeroSSH (off by default). It never takes over a scheme another program already handles; pick FeroSSH in Windows' Default apps instead. A link names a host and nothing else, so a link can't add options to FeroSSH's command line. Ctrl+click in the terminal now also opens plain-text `http`, `https`, `ssh` and `sftp` links, and `ssh://` and `sftp://` ones open in a new FeroSSH tab after a confirmation.

## In the terminal

- **Font ligatures.** Settings > Font ligatures (off by default) joins `->`, `=>`, `!=`, `===` and the like in fonts that have them, such as Cascadia Code, Fira Code and JetBrains Mono. Windows' own DirectWrite does the shaping, so nothing is added to the exe. Every character keeps its own cell, and ligatures break at the cursor, selections and colour changes.

## Fixes

- Menus could still come back without their names after switching window colours from a grey or tinted look to Light or Follow Windows. A menu FeroSSH has drawn once now stays drawn by FeroSSH, in Windows' light colours when window colours are off.

## Security

- The SSH worker now refuses channels a server opens that FeroSSH never asked for (`session`, `direct-tcpip` and `direct-streamlocal`). It accepts a `forwarded-streamlocal` channel only for a socket this connection forwards. A server could open these before, although nothing in FeroSSH answered on them.
- A worker can ask the window to connect somewhere only for a SOCKS-on-the-server forward, and only to a plain host name or address.

## For maintainers

- The IPC protocol between the window and the worker is now version 25.
- New fuzz target `dns_reply` for the SSHFP lookup. `host_config`, `forward_parse` and `sanitize` cover known_hosts listing, the new forward forms, `ssh://` links and plain-text links.
- Tag with git on your PC (`git tag v1.5.1 <merge commit> && git push origin v1.5.1`), then run `pwsh scripts/sign-release.ps1 -Tag v1.5.1` (PowerShell 7, GitHub CLI 2.93 or later).

## Downloads

| File | What it is |
| --- | --- |
| `ferossh.exe` | The standard client. |
| `ferossh-desktop.exe` | The same client plus a built-in RDP and VNC viewer that shows a remote desktop in a FeroSSH tab, in a sandboxed viewer process. |
| `ferossh-arm64.exe`, `ferossh-desktop-arm64.exe` | The same two for Windows on ARM. |
| `ferostream-agent` | The FeroStream agent for 64-bit Intel and AMD Linux hosts, for remote apps. Keep it next to the exe. |
| `ferostream-agent-aarch64` | The same agent for 64-bit ARM Linux hosts, such as a Raspberry Pi. |

The Linux agents are not code signed, but `SHA256SUMS.txt` and the build provenance cover them as well. To build them yourself, see [FeroStream agents](https://github.com/jkobierczynski/FeroSSH#ferostream-agents) in the README.
