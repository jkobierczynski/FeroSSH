# FeroSSH v1.4.1

*Secure connections. Forged in Rust.*

FeroSSH 1.4.1 adds a built-in library of a few hundred ready scripts, makes the command suggestion keys work the way fish and zsh users expect, and hands the keyboard back properly when the standby window hides. It also pins the Windows build tools so the reproducible build check holds when GitHub updates its runners. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) are the place to start.

## New

- **A built-in script library.** FeroSSH now carries a few hundred ready one-liners and scripts inside the exe. Session > Scripts > Write built-in scripts to the library... writes them into a `Library` folder in the scripts pane, grouped in categories such as Linux, System administration, Windows (PowerShell), Networking, Network devices (Cisco IOS and Juniper Junos), Security & hardening, Databases, Containers & Kubernetes, Cloud, Virtualization, Development and Hacking (recon and enumeration, for systems you are allowed to test). They are ordinary scripts: arguments, variables, hotkeys, search and running on several hosts all work. Nothing is written until you ask, and writing the library again never touches a script you edited or deleted unless you choose to overwrite. Run it again after an upgrade to pick up new scripts. Script categories in the pane now start folded, and FeroSSH remembers which ones you leave open.
- **Suggestion keys in Settings > Key bindings.** A greyed command suggestion is now also taken with **Ctrl+E** or **Ctrl+F**, as in fish and zsh-autosuggestions, next to Right arrow and End. Ctrl+Right takes its next word, Ctrl+Up and Ctrl+Down show other matches, and Shift+Delete forgets the one shown. All of them are listed under *Suggestions* in the Key bindings window and can be changed there. They only act while a suggestion shows; otherwise the key goes to the terminal as before, and the tmux prefix and the key after it still go to tmux.

## Fixed

- Pressing Ctrl+E while a suggestion showed made it vanish and not come back until the next key, because Ctrl+E went to the shell, which echoed nothing.
- When the standby hotkey hides the standby window, the keyboard goes back to the window that was in front before it came up, such as the FeroSSH pane you were typing in, instead of whichever window Windows picked next.

## For maintainers

- Release builds now use **MSVC v14.44** and **Windows SDK 10.0.26100.0** explicitly instead of the newest toolset on the machine. GitHub rolled out a new ARM64 runner image (Visual Studio 18.12) between the build and the rebuild job, which changed the C runtime linked into the exes and failed the reproducible build check; nothing in FeroSSH itself was non-deterministic. `scripts/build-release.ps1` records the tool versions in `dist/build-tools-<arch>.txt`, and the reproducible build job shows both builds' versions side by side. Rebuilding this release yourself needs the v14.44 build tools (an individual component of Visual Studio). The exes' bytes change once because of the new linker.
- Tag with git on your PC (`git tag v1.4.1 <merge commit> && git push origin v1.4.1`), then run `pwsh scripts/sign-release.ps1 -Tag v1.4.1` (PowerShell 7, GitHub CLI 2.93 or later).

## Downloads

| File | What it is |
| --- | --- |
| `ferossh.exe` | The standard client. |
| `ferossh-desktop.exe` | The same client plus a built-in RDP and VNC viewer that shows a remote desktop in a FeroSSH tab, in a sandboxed viewer process. |
| `ferossh-arm64.exe`, `ferossh-desktop-arm64.exe` | The same two for Windows on ARM. |
| `ferostream-agent` | The FeroStream agent for 64-bit Intel and AMD Linux hosts, for remote apps. Keep it next to the exe. |
| `ferostream-agent-aarch64` | The same agent for 64-bit ARM Linux hosts, such as a Raspberry Pi. |

The Linux agents are not code signed, but `SHA256SUMS.txt` and the build provenance cover them as well. To build them yourself, see [FeroStream agents](https://github.com/jkobierczynski/FeroSSH#ferostream-agents) in the README.
