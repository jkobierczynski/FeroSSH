# FeroSSH v0.1.0

*Secure connections. Forged in Rust.*

FeroSSH is a small, security-focused, open-source SSH client for Windows. It is meant as a native replacement for PuTTY: tabs, splits, tmux integration, file transfer, port forwarding and remote desktops, in one exe of about 3 MB that you download and run. There is no installer, no runtime and no Electron, Qt or Java inside.

This is the first release. Everything below works today, and it has been tested against real OpenSSH, tmux, xrdp and VNC servers in CI and by hand on Windows.

## Why FeroSSH

- **Native and small.** Win32 with DirectWrite/Direct2D rendering, written in Rust. `ferossh.exe` is about 3.2 MB and runs on a clean Windows 10 1903 or later.
- **Sandboxed by design.** FeroSSH runs as two processes. The window never parses network data. The SSH worker, which does, runs in an AppContainer with network access only: it cannot read your files or your private keys, and it asks the window for every signature.
- **Modern crypto only.** Post-quantum `mlkem768x25519-sha256` key exchange comes first. SHA-1, CBC, DSA and `ssh-rsa` signatures are not offered. Older switches and routers can be allowed per host, and the tab then shows an amber ⚠.
- **Your keys stay where they are.** Windows OpenSSH agent, Pageant, key files, FIDO2 security keys and passkeys. Passwords are never stored.
- **OpenSSH config is the session format.** Your `~/.ssh/config` works as it is, and FeroSSH never writes to it.

## What's in v0.1.0

**Terminal, tabs and splits.** One clean pane by default; the tab strip appears when you open a second tab. Split panes in any direction, drag tabs and panes around, join a tab back in as a pane. A new tab on a host you're already logged in to reuses the connection, so there is no second login. Scrollback with search, OSC 8 links, PuTTY-style copy-on-select and right-click paste if you want them, and a log file per tab.

**Session manager.** A side pane with your hosts from `~/.ssh/config`, favourites and folders, filtered as you type. Saved sessions need no ssh_config at all: a form for host, user, port, key file, look (theme, font, size, scrollback) and extras (tmux session, port forwards, RDP/VNC ports, older crypto). Sessions can be SSH terminals, RDP desktops or VNC desktops.

**PuTTY import.** File > Import PuTTY sessions brings over your saved PuTTY sessions. `.ppk` keys (v2 and v3) work for Ed25519 and ECDSA P-256; RSA `.ppk` keys work through Pageant.

**Themes and per-host colours.** Twelve built-in themes (Nord by default, plus Dracula, Catppuccin Mocha, Gruvbox, Solarized, Tokyo Night and more) and two warning themes, **Production** (red) and **Staging** (amber). Rules pick the theme by host pattern or ssh_config `Tag`, so production servers always look like production. Font, size and theme can differ per tab and per pane.

**tmux integration.** Session > Attach tmux turns tmux windows and panes into native tabs and panes: no prefix key, no status bar, native scrollback, copy and search. Each pane can have its own font and theme, and the layout and looks are stored in tmux itself, so you can close FeroSSH, attach from another PC and get everything back. tmux is never started unless you ask for it.

**File transfer over SFTP.** Ctrl+Shift+E opens the pane's host in the side pane, on the same connection. Drag and drop from Explorer, a transfer queue with pause, resume and retry, resume after a dropped connection, optional SHA-256 verification, and the file view can follow the shell's `cd`. Files are never overwritten without asking, and server names Windows cannot hold are made safe.

**Port forwarding and X11.** Local, remote and dynamic forwards (SOCKS 4, 4a and 5) from ssh_config or added live in the Port forwards panel. X11 forwarding to an X server on Windows such as VcXsrv, off unless a host turns it on, with the real X cookie never sent to the server.

**Security keys and passkeys.** FIDO2 `sk-ssh-ed25519` and `sk-ecdsa-sha2-nistp256` keys through Windows' own WebAuthn dialog: a USB or NFC key, Windows Hello, or your phone as a passkey. `ferossh.exe --new-security-key` makes a new key file. Also supported: host and user certificates, ECDSA P-384/P-521 keys in an agent, keyboard-interactive and one-time codes.

**Host key safety.** New hosts show their SHA-256 fingerprint and randomart; a changed key fills the window with a warning that cannot be clicked away.

**Remote Linux desktop.** Session > Open remote desktop (Ctrl+Shift+D) tunnels the server's RDP port through the SSH connection and opens Windows' Remote Desktop Connection on it. Works with xrdp and GNOME Remote Desktop, on X11 or Wayland, and nothing new is opened on the server's firewall.

## Two downloads

| File | What it is |
| --- | --- |
| `ferossh.exe` | The standard client, about 3.2 MB. Contains no desktop viewer code. |
| `ferossh-desktop.exe` | The same client plus a built-in RDP and VNC viewer that shows the remote desktop in a FeroSSH tab. Everything the desktop server sends is handled in a separate viewer process in an AppContainer with no capabilities at all, and it only ever connects through the SSH tunnel. |

## Getting started

```
ferossh.exe                    # asks for a host
ferossh.exe user@host
ferossh.exe myalias            # a Host from ~/.ssh/config
ferossh.exe --theme Production prod-db
```

Ctrl+Shift+S opens the session manager, Ctrl+Shift+T a new tab, Alt+Shift+= and Alt+Shift+- split the pane. The README has the full list of shortcuts and settings.

## Known limitations

- The exe is not code-signed yet, so Windows SmartScreen and some browsers will warn when you download or first run it.
- Windows does not let the sandboxed worker reach 127.0.0.1; use `--no-sandbox` for an SSH server on the same machine.
- RSA keys work only through an agent (OpenSSH agent or Pageant), and need 3072 bits or more.
- The built-in desktop viewer has no clipboard sharing yet.
- No ZMODEM, and no remote mkdir or rename in the file view yet.
- Coming next: more password sources for saved sessions, and importing sessions from other SSH clients.
