# FeroSSH v1.5.0

*Secure connections. Forged in Rust.*

FeroSSH 1.5.0 makes FeroSSH a good home for coding agents such as Claude Code, Codex and aider on remote hosts. You can start them in tmux so they outlive a dropped connection, see in one dashboard which of them wait for you, and get a Windows notification when one stops. You can also answer an agent's yes-or-no question from that notification, paste a screenshot straight into its prompt, open the web server it started, and look at what it changed in a side-by-side diff. The terminal can now show pictures that programs on the host print (Sixel, kitty graphics and iTerm2 images). The window can take eight soft tinted colours, themes and colours show as you hover over them, and you can save your own themes. Workspaces can log in by themselves and reopen at start, and File transfer lets you drag remote files straight out to Explorer. Every new feature is off until you turn it on. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) are the place to start.

## Coding agents on remote hosts

Everything here is under **Session > Coding agents**. The [Coding agents in tmux](https://github.com/jkobierczynski/FeroSSH/blob/v1.5.0/docs/guide/everyday-use.md#coding-agents-in-tmux) section of the guide shows how the parts fit together.

- **Start an agent in tmux.** *Start claude in tmux* (and *codex* and *aider*, or your own `AgentCommand` lines in `ferossh.conf`) opens the agent in a new tmux window on the pane's server, in the pane's directory, as a new tab. If the host already shows a tmux session, the agent joins it. Otherwise FeroSSH uses a session called `agents` and attaches it. tmux keeps the agent running when the connection drops, and automatic reconnect brings the tab back.
- **Agent dashboard.** *Agent dashboard (who waits for you)* opens the Session manager as one list of every agent on every connected host. It shows the host, the tab, what each agent is doing (*working*, *needs you*, *quiet*, *idle*), for how long, and the last line it showed. The agents waiting for you come first, the longest wait on top, and Enter goes to the agent's pane.
- **Notifications.** With **Settings > Desktop notifications** on, a pane that wants you gets an amber ◆ on its tab, and Windows shows a notification when you are not looking at that pane. Clicking it brings FeroSSH forward on that pane. A pane asks for attention when the host sends a notification (OSC 9, OSC 777 or OSC 99, which Claude Code, Codex, kitty, Ghostty and shell hooks use) or rings the bell. With **Session > Notify when this pane goes quiet**, it also asks when its output stops after some work, for programs that never say they are done. Agent panes are watched this way automatically. This works for long builds too, not just agents.
- **Answer yes or no from the notification.** With *Answer yes-or-no questions from the notification* on, an agent stopped at a question such as "Do you want to make this edit?" or `[y/n]` shows the question in its notification. Clicking it asks Yes, No or Cancel in a small dialog, without switching tabs. FeroSSH reads the screen again and types the answer only if the same question is still showing.
- **Paste screenshots and files.** With *Paste and drop files: upload and type the path* on, pasting an image (Ctrl+Shift+V) or files copied in Explorer, or dropping files on a pane, uploads them to `~/.cache/ferossh/paste/` on the pane's host and types their paths at the cursor, ready for the agent to read. Text still pastes as text.
- **Open the web server an agent started.** With *Offer to forward and open web servers on the host* on, an address such as `http://localhost:5173/` in a pane's output shows a small bar. **Forward and open** adds an ordinary local port forward and opens your browser on it. Nothing is forwarded without that click.
- **See what changed.** *Show what changed here (side-by-side git diff)* opens a tab with the changes in the git repository the pane or its agent works in, compared with the last commit, with old and new side by side and untracked files shown as added. Press r to look again and n or p to go from file to file. Git runs on its own channel of the pane's connection, and everything it prints is shown as plain text.
- **Keys agents understand.** *Kitty keyboard protocol for programs that ask for it* lets an agent tell Escape, Shift+Enter and Ctrl or Alt keys apart. *Shift+Enter types a new line (sends Esc Enter)* gives a new line in the agent's input box, also inside tmux.
- **Production hosts and an audit trail.** The Production guard is now called **Confirm scripts and agents on Production hosts**. On a host with the red Production theme it asks before starting an agent and before text, images or files are pasted or dropped into an agent's pane. *Log and record agent panes (audit trail)* keeps a sealed log and recording of every agent pane from the moment it opens.

## Images in the terminal

**Session > Show images the host prints (Sixel, kitty, iTerm2)** (`InlineImages yes`) shows plots, thumbnails and previews that programs print with Sixel (`img2sixel`, `chafa`, `lsix`, gnuplot), the kitty graphics protocol (`kitten icat`, `timg`) or iTerm2 inline images (`imgcat`, PNG only). Pictures scroll with the text and go into the scrollback, and they work in tmux panes too.

Every picture is data from the host, so this is off by default. FeroSSH decodes pictures with its own small decoders, written in safe Rust and fuzzed, with firm limits on size and memory. A host can never make FeroSSH read a file on this PC: the kitty protocol's file and shared-memory modes are refused.

## Looks

- **Tinted window colours.** Settings > Window colours adds eight soft neutrals that aren't grey: **Sand**, **Sage**, **Mist** and **Taupe** (light), and **Slate**, **Moss**, **Espresso** and **Heather** (dark). Text on each reads at 4.5:1 or better. With window colours on, menus and submenus now take the menu bar's colours as well.
- **Live preview.** Resting the mouse or keyboard on a theme, custom theme or window colour in a menu shows it at once, in the focused pane and the window around it. Closing the menu without picking puts the old look back. Fonts are not previewed, because a new size would resize the remote terminal.
- **Custom themes.** Settings > Custom themes (font and colours) lists your own themes, one `.theme` text file each in the `themes` folder. A theme holds a palette (optionally starting from a built-in one), and can also set a font, a text size and window colours. **Save this look as a theme...** saves the focused pane's look, and **Open themes folder** opens the folder for editing. Host rules, profiles and `--theme` can name custom themes too. The [file format](https://github.com/jkobierczynski/FeroSSH/blob/v1.5.0/docs/guide/everyday-use.md#custom-themes) is in the guide.

## Workspaces

- **Log in automatically.** With Window > Workspaces > Log in automatically on, a connection in a workspace that would ask for its password asks once and keeps it, in the vault when a master password is in use, otherwise in the Windows Credential Manager. Connections you open by hand are not affected.
- **A script or command per pane.** A workspace pane can have a `Script NAME` or `Command TEXT` line that runs once the pane is logged in and in its directory. FeroSSH asks before running any line this PC hasn't approved yet, and asks again when a script changes.
- **Reopen the last layout at start.** With this on, the tabs and panes open when FeroSSH closes come back at the next plain start.

## File transfer

- **Drag out to Explorer.** Drag files and folders from the Remote list out to Explorer, the desktop or any program that takes dropped files. They download through the usual transfer queue, with the usual checks, and are marked as downloaded from the Internet. Esc cancels.

## Fixes

- After switching Settings > Window colours from a tinted or grey look back to Light or Follow Windows, menus showed no item names. They do again.

## Before you upgrade

Nothing changes until you turn it on: every new option is off by default. One menu item was renamed: Session > Scripts > Confirm scripts on Production hosts is now *Confirm scripts and agents on Production hosts*, with the same `ConfirmProduction` setting. The guide's [menu reference](https://github.com/jkobierczynski/FeroSSH/blob/v1.5.0/docs/guide/menus.md) lists every new item.

## For maintainers

- [DEVELOPMENT.md](https://github.com/jkobierczynski/FeroSSH/blob/v1.5.0/DEVELOPMENT.md) is the project's development history, and each release's version bump pull request now adds that release to it.
- New fuzz targets `image_decode` and `image_feed` cover the picture decoders and the terminal with pictures on. The CI smoke run picks them up.
- Tag with git on your PC (`git tag v1.5.0 <merge commit> && git push origin v1.5.0`), then run `pwsh scripts/sign-release.ps1 -Tag v1.5.0` (PowerShell 7, GitHub CLI 2.93 or later).

## Downloads

| File | What it is |
| --- | --- |
| `ferossh.exe` | The standard client. |
| `ferossh-desktop.exe` | The same client plus a built-in RDP and VNC viewer that shows a remote desktop in a FeroSSH tab, in a sandboxed viewer process. |
| `ferossh-arm64.exe`, `ferossh-desktop-arm64.exe` | The same two for Windows on ARM. |
| `ferostream-agent` | The FeroStream agent for 64-bit Intel and AMD Linux hosts, for remote apps. Keep it next to the exe. |
| `ferostream-agent-aarch64` | The same agent for 64-bit ARM Linux hosts, such as a Raspberry Pi. |

The Linux agents are not code signed, but `SHA256SUMS.txt` and the build provenance cover them as well. To build them yourself, see [FeroStream agents](https://github.com/jkobierczynski/FeroSSH#ferostream-agents) in the README.
