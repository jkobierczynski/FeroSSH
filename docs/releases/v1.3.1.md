# FeroSSH v1.3.1

*Secure connections. Forged in Rust.*

FeroSSH 1.3.1 turns the tools beside the terminal into native Windows controls, with a tools rail, a file transfer view with two lists and bookmarks, and window colours that can follow your theme. Snippets become Scripts, with Expect-style logic. There is also a round of security hardening from a code audit, and a stricter signing check for releases. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) introduce it.

## New

- **A native tools pane and rail.** The Connection manager, Session manager, connection form, File transfer, Port forwards and Scripts are now native Windows controls (tree and list views, search boxes, buttons and right-click menus) that use the system font at your screen's scaling. A narrow rail of tool icons on the window's edge opens and closes each tool. The terminal's edge slides over the open tool instead of squeezing it: drag it to cover the tool partly or completely. Settings > Tools rail and Keep tools open turn them off. With Keep tools open off, an opened tool is a peek that a click in the terminal or Esc covers again.
- **File transfer with two lists.** Local and Remote lists side by side or stacked, with system icons, multi-select, arrow buttons to upload or download, drag and drop between the lists, from Explorer and onto a terminal pane, and a transfer queue with progress bars. **Bookmarks** keep pairs of Local and Remote folders, for any host or one connection. **Sync** browses both lists together. A connection can have its own *Local folder* and *Remote folder* to start in.
- **Window colours.** Settings > Window colours chooses how the menu bar, menus, title bar, tab strip and tools pane are coloured. You can follow the terminal's colour theme (a dark theme gives a dark window), follow Windows' light or dark mode, or pick Light (the default, as before) or Dark.
- **Scripts with logic.** Command snippets are now called Scripts and live in `%APPDATA%\FeroSSH\scripts` (an old snippets folder moves there once, and `.snippet` files are still read). Scripts and login scripts gain Expect-style steps: `@on` to wait for whichever text comes first, `@label`, `@goto` and `@if`, `@timeout`, and `@set`/`@add` variables with `${captured}` from `@capture`. Text from the host only ever stays text: it can't become a key, a step or a second line. A script that loops without waiting is stopped.

## Security

- **Resumed transfers are always checked.** A resumed upload or download is now verified with SHA-256 before the partial file is kept. If it can't be verified, the part file stays and the queue says which one to delete. The remote checksum command no longer has the file name on its command line, where a name like `a&calc&rem` could run a program on a Windows server's shell.
- **Bounded memory for slow servers.** A session whose server stops reading what you type or paste is closed at 32 MiB, with a message saying why, instead of growing without limit or stalling your other sessions. SFTP reads ahead only within its window, and at most four remote checksums run at once and stop when SFTP ends. Session logs and tmux control mode cap long lines and replies.
- **Host certificates** with critical options FeroSSH doesn't understand are refused.
- **Local shells** only start `cmd.exe` or PowerShell from System32, the Windows folder or absolute PATH folders, so a `cmd.exe` planted next to `ferossh.exe` (in Downloads, say) never runs instead.
- **Smaller fixes.** Text-direction characters in remote file names become `_` locally. A virtual desktop's xauth cookie no longer shows on a command line. Script recording no longer records a password that only looks like its echo. Cells in run reports that start like a formula are prefixed with `'` in CSV and copied tables.
- **Stricter release signing.** Before signing, `sign-release.ps1` now checks with `gh attestation verify` that the unsigned exes and the manifest are the ones this tag's release run built. After signing, it checks that each signed exe differs from its attested build only by the signature. The attest workflow repeats every check and only runs from main.

## Fixed

- File transfer no longer keeps a stale selection, or acts on the wrong folder or host, when the pane switches while a menu or question is open.

## For maintainers

`scripts/sign-release.ps1` now needs **PowerShell 7** (`winget install Microsoft.PowerShell`) and **GitHub CLI 2.93 or later** (`gh --version`; `winget upgrade GitHub.cli`), for `gh attestation verify --source-ref --source-digest` and for the fix to GHSA-8xvp-7hj6-mcj9, in which older versions could send the gh credential to TUF mirrors during `gh attestation verify`. While the release is still a draft, running the script again after a failure signs afresh from CI's unsigned exes. If only the winget manifests failed after publishing, run `scripts/winget-manifest.ps1` on its own instead.

## Downloads

| File | What it is |
| --- | --- |
| `ferossh.exe` | The standard client. |
| `ferossh-desktop.exe` | The same client plus a built-in RDP and VNC viewer that shows a remote desktop in a FeroSSH tab, in a sandboxed viewer process. |
| `ferostream-agent` | The FeroStream agent for 64-bit Intel and AMD Linux hosts, for remote apps. Keep it next to the exe. |
| `ferostream-agent-aarch64` | The same agent for 64-bit ARM Linux hosts, such as a Raspberry Pi. |

The Linux agents are not code signed, but `SHA256SUMS.txt` and the build provenance cover them as well.
