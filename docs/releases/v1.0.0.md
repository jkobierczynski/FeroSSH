# FeroSSH 1.0

*Secure connections. Forged in Rust.*

FeroSSH is a native, open-source SSH client for Windows that locks every connection in its own AppContainer sandbox, away from your keys and files. It gives you tabs, splits, tmux integration, port forwarding, snippets and file transfer in one signed exe of about 4 MB, with nothing to install. There is no runtime and no Electron, Qt or Java inside.

1.0 is the first stable release. It comes after two release candidates, and everything described here is tested in CI against real OpenSSH, tmux, Telnet, xrdp and VNC servers.

## Why another SSH client

An SSH client reads whatever a server sends it, and on most clients the code that does that runs with all of your rights: it can read your private keys, your documents and every other connection you have open. FeroSSH is built so that a malicious or compromised server gets as little as possible:

- **One sandbox per connection.** Each connection, and each jump host on the way, runs in its own worker process inside an AppContainer. The worker can reach the network and nothing else. It cannot read your files or your keys, and it asks the window for every signature. A worker taken over by one server cannot see your other sessions.
- **A window that never parses network data.** The window checks every message a worker sends it. Workers run with no Win32k system calls, Control Flow Guard, CET shadow stacks where the CPU has them, no dynamic code and a memory cap. `ferossh.exe --check-sandbox | more` shows what your Windows allows.
- **Modern crypto first.** Post-quantum `mlkem768x25519-sha256` key exchange comes first. SHA-1, CBC, DSA and `ssh-rsa` signatures are not offered by default. Older switches and routers can be allowed per host, and their tab is marked.
- **Your keys stay where they are.** Windows OpenSSH agent, Pageant, key files, FIDO2 security keys and passkeys (including your phone). FeroSSH never stores a password itself: it takes them from the Windows Credential Manager, 1Password, Bitwarden, KeePassXC or your own command.
- **Fuzzed every night.** Every parser that sees network data (SSH transport, SFTP, Telnet, ZMODEM, tmux, RDP, VNC, the terminal itself) has a fuzz target. Inputs that ever crashed one are kept and tried again on every change.

[SECURITY.md](https://github.com/jkobierczynski/FeroSSH/blob/main/SECURITY.md) describes the model and its limits.

## What it does

**A quiet terminal.** One pane and no tab strip until you need more. Split in any direction, drag tabs and panes around, and open a new tab on a host you're logged in to without a second login. Font, size and colour theme can differ per tab and per pane. Production servers can turn red and staging amber automatically, by host name or ssh_config `Tag`.

**Your sessions, wherever they are now.** `~/.ssh/config` works as it is, including `ProxyJump` and `ProxyCommand`. Saved sessions live in the Connection manager (Ctrl+Shift+S), and you can import them from PuTTY, KiTTY, WinSCP, MobaXterm, mRemoteNG and SecureCRT. The Session manager (Ctrl+Shift+L) lists everything you have open right now.

**More than SSH.** Serial consoles (`COM3:115200`) and Telnet for network gear that has nothing better. The remote Linux desktop is tunnelled through SSH, either with Windows' Remote Desktop or with the built-in viewer in `ferossh-desktop.exe`.

**Files and ports.** SFTP in a side pane on the same connection, with drag and drop, a resumable queue and optional SHA-256 checks. ZMODEM (`rz`/`sz`) for hosts without SFTP. Local, remote and SOCKS forwards, which you can change while connected, and X11 forwarding.

**tmux, natively.** Session > Attach tmux turns tmux windows and panes into real FeroSSH tabs and panes, with no prefix key and native scrollback. The layout is kept in tmux, so you get it back from any PC.

**Less typing.** A command palette (Ctrl+Shift+A) over every action, session and snippet. Command snippets with arguments, variables, `@expect`/`@capture` steps and hotkeys. Run one snippet on many saved hosts at once, with a live report of what each one answered. Login scripts, auto-responses to `--More--`, broadcast input across panes, and a confirmation before anything is typed into a Production pane.

**It stays connected.** When Wi-Fi changes or the laptop sleeps, the tab stays where it is and logs in again by itself. Forwards, tmux and transfers pick up where they left off.

**Logs you can trust.** A log file per tab, with optional timestamps on each line. Every log is sealed with a SHA-256 hash chain that shows whether it was changed afterwards.

## Getting started

Download `ferossh.exe`, put it anywhere and run it:

```
ferossh.exe                   # asks for a host
ferossh.exe user@host
ferossh.exe myalias           # a Host from ~/.ssh/config
ferossh.exe COM3:115200       # a serial console
```

Ctrl+Shift+T opens a tab, Alt+Shift+= and Alt+Shift+- split the pane, Ctrl+Shift+S opens the Connection manager and Ctrl+Shift+A finds everything else. The [user guide](https://github.com/jkobierczynski/FeroSSH/tree/main/docs/guide) covers everyday use, every setting, the security model and troubleshooting.

## Checking what you downloaded

- **Code signing.** Both exes are signed with a Certum Open Source code signing certificate, with a timestamp. Because the certificate is new, Windows SmartScreen may still warn for a while until it has built up a reputation.
- **Reproducible builds.** Anyone can rebuild this release from its tag and get the same bytes. `BUILD-MANIFEST.json` gives each exe's SHA-256 before and after signing.
- **Build provenance.** `gh attestation verify ferossh.exe -R jkobierczynski/FeroSSH` shows that the file came from this repository's release workflow.
- **Signed updates.** Help > Check for updates (and an optional weekly check, off by default) reads a small update file and checks its Ed25519 signature before trusting it. Nothing is downloaded or installed for you.

[Verifying a download](https://github.com/jkobierczynski/FeroSSH/blob/main/docs/guide/verifying-downloads.md) walks through each check.

## Known limitations

- Windows does not let the sandboxed worker reach 127.0.0.1; use `--no-sandbox` for an SSH server on the same machine.
- RSA keys work only through an agent (OpenSSH agent or Pageant), and need 3072 bits or more.
- The built-in desktop viewer has no clipboard sharing yet.
