# FeroSSH v1.6.0

*Secure connections. Forged in Rust.*

FeroSSH 1.6.0 is about looking after many servers, alone or as a team. Connections get several tags, a search language and saved searches, and you can change a field on forty of them at once. New pages in the tools pane manage named credentials, security rules, theme rules, themes, hosts and a real connection log. A team can share one signed, read-only library of connections and rules, and an organisation can enforce that library and keep the connection log by machine policy (Group Policy or Intune). There are also shared tmux sessions, GitHub Dark as the new default theme, and fixes for servers that allow few sessions per connection, such as tinysshd. Several defaults change; see **Before you upgrade**. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) are the place to start.

## Before you upgrade

- **GitHub Dark is the default theme.** New tabs open in GitHub Dark instead of Nord, unless a connection, a rule or `--theme` picks another. Tools > Theme manager > Set as default (or `DefaultTheme Nord` in `ferossh.conf`) brings Nord back. A custom `.theme` file without a `Base` line still starts from Nord, so its colours stay as they were.
- **Hosts tagged `production`, `staging` or `development` always get their warning theme.** The built-in tag rules (Production, Staging and Nord, also for `prod`, `stage` and `dev`) are now enforced: a connection's own theme, a rule of yours or a pane setting no longer changes them. Your rules can still give those hosts a font and size.
- **FeroSSH asks when a connection has lost security limits.** It remembers the limits each connection had when it last connected, and asks before connecting when a tag, folder, name or rule change took some away. See [When a connection loses limits](https://github.com/jkobierczynski/FeroSSH/blob/v1.6.0/docs/guide/everyday-use.md#when-a-connection-loses-limits).
- **Tools > Connection log is now a real log.** It lists every connection made (connected, disconnected, lost, failed), not one row per connection. What the old page showed per machine is on the new Tools > Hosts page. The setting *Allow deleting connection log entries* is gone: you can delete entries after a question unless your organisation's policy forbids it.
- **Log timestamps show when a line ended.** Session > Logs and recordings > Timestamp each log line now stamps the time a line was finished, so a command line shows when you pressed Enter.

## Managing many connections

- **Several tags per connection.** The connection form has a **Tags** box (`prod web eu`). Tags show in the connection manager, the tooltip, the command palette and the script host picker, and work on hosts from `~/.ssh/config` too (FeroSSH keeps them in its own settings, never in your ssh_config).
- **Search by field.** The connection manager's search box takes `tag:prod`, `folder:db`, `user:root`, `host:10.0.`, `addr:db.example`, `type:rdp`, `port:2222`, `-tag:legacy` to leave out, and quotes for spaces. Right-click while a search is typed to **save it as a folder**.
- **Act on many at once.** Ctrl+click, Shift+click and Ctrl+A select several connections. Right-click for Connect to all, Add tag, Remove tag, Move to folder, Delete, and **Change a field**: user, key file, jump hosts, proxy, password source, credential, theme, font and more, with a preview of each connection's old and new value before anything changes.
- **Named credentials.** A credential is a named login (user, key file, password source) that many connections share. Change it once and every connection that uses it logs in the new way. Secrets stay where they were. **Tools > Credential manager** lists your credentials and the passwords FeroSSH keeps, each with what uses it.
- **Tools > Hosts** shows one row per machine: the connections that reach the same address, with their users, ports, tags, latest login, host key and, optionally, the OS and kernel (**Read OS** in a connection's Extras runs one fixed read-only command after login).
- **Tools > Connection log** (Ctrl+Shift+I) lists every connection FeroSSH made on this PC, with the address, jump hosts, proxy, host key fingerprint and why it ended or failed. Search, sort, connect again, save as CSV. While a master password vault is open, the log and the Hosts data are encrypted with it.

## Security rules

- **Security rules by tag, folder or host.** A rule can allow keys only, keep passwords out of the Windows Credential Manager, turn off agent forwarding, keep the server off your clipboard (in the terminal, desktop viewers and remote apps), ask before connecting, or force a session log that cannot be turned off. Rules only add limits, and a connection lists the ones that apply when it starts. **Tools > Security rules** (the padlock) lists them with the connections each covers, so a rule that covers nothing, or far too much, stands out.
- **Rules follow the machine.** An address typed at Connect to... or an `ssh://` link gets the limits of every saved connection to the same host name.
- **Rules are not lost by accident.** A rule line FeroSSH does not understand stays in the file and is flagged with ⚠ instead of being dropped. Rules another window or PC added (through a shared vault) are kept when this one saves. Removing a tag, moving or renaming a connection asks first when it would lose limits, and connecting asks when limits are gone since last time (see **Before you upgrade**).
- **Encrypted imports show what they change**: host, port, user, jump hosts, proxy, forwarding, keys, password source, credential and login script for each connection they replace. Imports keep your tags and folders, and leave out `StrictHostKeyChecking no` or `accept-new` from the file.
- A Remote Desktop or VNC connection through Via SSH now asks under `ConfirmConnect` before its tunnel opens.

## Team library

- **One signed library for a team.** An administrator exports connections, security rules, theme rules and the custom themes they use with **File > Import and export > Export team library**, signs the file with an SSH key (`ssh-keygen -Y sign -n ferossh-library`) and puts it on a share. Everyone else sets the file and the public key in **Settings > Team library**. The team's connections show read-only in a **Team** folder, and the team's rules apply first; nobody can change, delete, retag or loosen them in their own FeroSSH. No password or credential travels in the library: each person keeps their own credential of that name.
- **No rolling back.** Each library is dated and the date is signed. FeroSSH refuses a library older than the one it used last, for each signing key, at any path, so putting an older signed file back on the share (or pointing Settings at one) does not undo a newer rule.
- Only key files in the user's home folder (`~/.ssh/id_team`) travel in a library; full paths from the exporting PC are left out.
- **Machine policy.** On managed PCs an administrator can set the library under `HKLM\Software\Policies\FeroSSH`, with Group Policy or Intune (an ADMX template is in [`docs/admin/policy`](https://github.com/jkobierczynski/FeroSSH/tree/v1.6.0/docs/admin/policy)). The policy's library wins over the user's, FeroSSH connects nowhere while it has no good library (unless that is turned off), and *Allow only the team library's connections* limits FeroSSH to the team's connections. See [Enforcing the team library by machine policy](https://github.com/jkobierczynski/FeroSSH/blob/v1.6.0/docs/admin/team-library-policy.md).

## Connection log policy (for administrators)

Two more machine policies cover the connection log: **Allow deleting connection log entries** (disable it to keep every entry) and **Copy the connection log to the Windows event log**, which writes each entry to the Application log, source `FeroSSH`, event IDs 1001 to 1005 and 1010, where users cannot remove it and your SIEM can collect it. The line under Tools > Connection log says whether the copy works.

Register the event source once per PC, as an administrator, so Event Viewer shows FeroSSH's text:

```
New-EventLog -LogName Application -Source FeroSSH
```

Without it, Event Viewer shows an unrelated Windows message on the General tab (FeroSSH's text is still under Details). See [Keeping the connection log by machine policy](https://github.com/jkobierczynski/FeroSSH/blob/v1.6.0/docs/admin/connection-log-policy.md).

## Looks

- **Tools > Theme manager** (the palette) lists the themes and the eighteen fonts with a preview, puts one on the pane, makes it the default for new tabs, or starts a rule with it. **Edit colours...** changes a theme's colours with swatches and `#RRGGBB` fields; built-in themes are never changed, only saved as a new theme.
- **Tools > Theme rules** (the tag) gives connections a theme, a font and a font size by tag or host, in order. **Enforce** makes a rule's look stick, so production always looks like production.
- New settings `DefaultTheme`, `DefaultFont` and `DefaultFontSize`.

## tmux

- **Shared sessions.** Session > tmux > Share this session lets a colleague watch your tmux session live: anyone logged in as you, or, with tmux 3.3 or later, other accounts you name, through a shared tmux server only they can reach. Join a shared session watches read-only, without resizing or rearranging the owner's windows. Stop sharing takes everyone else off. tmux keeps other accounts watch-only only from 3.9; on older tmux FeroSSH lets them in only to type, after saying that this gives them your account.
- Closing a tab or pane of a tmux session that another client also shows now asks first. Yes (the default) detaches this connection so the other clients keep everything; No closes the panes for everyone.

## Fixes

- **"Failed to open channel (AdministrativelyProhibited)".** Closed panes, tabs and file transfers left their session channel open on a shared connection, so after ten (OpenSSH's `MaxSessions`) new panes and reconnects were refused. They are now closed.
- **tinysshd and other servers with one session per connection.** When a server refuses another session on a shared connection, the new pane logs in on its own connection, and later panes on that host do the same. File transfer on such a server needs an SFTP connection of its own.
- Session log timestamps no longer lag behind on prompt lines (see **Before you upgrade**).

## For maintainers

- The IPC protocol between the window and the worker is still version 25.
- Tag with git on your PC (`git tag v1.6.0 <merge commit> && git push origin v1.6.0`), then run `pwsh scripts/sign-release.ps1 -Tag v1.6.0` (PowerShell 7, GitHub CLI 2.93 or later).

| File | What it is |
| --- | --- |
| `ferossh.exe` | The standard client. |
| `ferossh-desktop.exe` | The same client plus a built-in RDP and VNC viewer that shows a remote desktop in a FeroSSH tab, in a sandboxed viewer process. |
| `ferossh-arm64.exe`, `ferossh-desktop-arm64.exe` | The same two for Windows on ARM. |

The Linux agents are not code signed, but `SHA256SUMS.txt` and the build provenance cover them as well. To build them yourself, see [FeroStream agents](https://github.com/jkobierczynski/FeroSSH#ferostream-agents) in the README.
