# FeroSSH v1.4.0

*Secure connections. Forged in Rust.*

FeroSSH 1.4.0 is the biggest release since 1.0. It adds new ways to connect: Mosh, WinRM, SFTP-only connections, SOCKS 5 and HTTP proxies, and Kerberos login. Workspaces bring back a whole set of tabs and panes in one go, and connections can travel between PCs in an encrypted backup or a master password vault. There are native Windows ARM64 builds, configurable key bindings, session recordings with replay, a server status bar, command suggestions and keyword highlighting, and the menus are reorganised. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) are the place to start.

## New ways to connect

- **Mosh.** A connection of type *Mosh terminal (SSH + UDP)* logs in over SSH as usual, then talks to `mosh-server` over UDP, so the session survives Wi-Fi changes, a new address and sleep. FeroSSH speaks the Mosh protocol itself in the sandboxed worker. On a slow link, what you type shows at once (**local echo**), underlined until the server confirms it, and text a program hides, such as a password, never shows. The host needs `mosh` installed and its UDP ports open.
- **WinRM.** PowerShell or cmd on Windows servers through their WinRM service, as `Enter-PSSession` does: `winrm://LAB\admin@win-srv` at the connect prompt or a *WinRM* connection. It uses HTTP on port 5985 with Negotiate (Kerberos or NTLM) and sealed messages, or HTTPS on 5986 (`winrms://`), and it takes passwords from the same password sources as SSH.
- **SFTP-only connections.** For accounts that allow only file transfer (`ForceCommand internal-sftp`, upload users, hosting), a connection of type *SFTP file transfer only*, or `sftp://user@host[:port][/folder]` at the connect prompt, logs in without asking for a shell and opens File transfer straight away. WinSCP's SFTP sites and MobaXterm's SFTP sessions import as such.
- **SOCKS 5 and HTTP proxies.** The connection form's *Proxy* field takes `socks5://` or `http://` (with a user if the proxy wants a login), for SSH, Mosh's SSH login and SFTP-only connections.
- **Kerberos login.** On a PC in a Windows domain, FeroSSH logs in to servers that accept `gssapi-with-mic` with your Windows logon's tickets, through SSPI, and can delegate them (`GSSAPIAuthentication`, `GSSAPIDelegateCredentials`, `GSSAPIServerIdentity`).
- **Agent forwarding.** `ForwardAgent yes` (or *Fwd agent* in a connection) lets `ssh` and `git` on the server use your agent's keys. FeroSSH asks before each signature.
- **More of your ssh_config.** `Match` blocks and more keywords, including `SendEnv`, `SetEnv`, `RemoteCommand`, `RequestTTY`, `HostKeyAlias` and `AddressFamily`.
- **New SSH key and Copy public key.** Tools > New SSH key... makes an Ed25519 key file (with a passphrase or not), a security key or a Windows Hello key. Session > Copy public key to this server... adds it to the host's `authorized_keys`, as `ssh-copy-id` does.

## Workspaces, backup and portable use

- **Workspaces.** Window > Workspaces > Save layout as workspace... keeps the open tabs and split panes, each with its connection, directory, session name and look. Open it again from the menu, the *Workspaces* folder in the connection manager, the command palette or `ferossh.exe --workspace NAME`. Panes on one host log in once, and tmux panes come back attached to their session; if the server has rebooted, FeroSSH makes the session again with its saved windows. A workspace never holds an address, key or password, so its plain text file is safe to copy or keep in git.
- **Encrypted backup and sync.** File > Import and export > Export connections... writes your connections and their settings to one `.ferossh` file sealed with a passphrase (Argon2id and ChaCha20-Poly1305). Saved passwords are included only if you tick the box. Import encrypted connections... shows what it would add and replace before it merges.
- **Master password.** Settings > Master password moves your connections, settings and saved passwords into one encrypted vault file, unlocked when FeroSSH starts. Put the vault in OneDrive and use it from several PCs: FeroSSH reloads it when another PC writes it and merges host settings rather than overwriting them.
- **Portable mode.** A folder named `FeroSSH-data` next to the exe makes FeroSSH keep everything there (settings, connections, `known_hosts`, logs, history, the vault), with no passwords in the Credential Manager.
- **Recent connections.** File > Recent connections lists the last eight hosts you connected to.

## In the terminal

- **Session recordings.** Session > Logs and recordings > Record this pane records what the host sends, with its timing, as an asciicast file that `asciinema play` and other players read. Play a recording... replays one in a FeroSSH tab at its own pace, with pause, speed and seek.
- **Server status bar.** Settings > Server status bar shows the CPU, memory, disk and network use of the focused pane's server in one quiet row under the panes, read by a small read-only command on its own channel of the same connection. It is off unless you turn it on.
- **Command suggestions.** Edit > Suggest commands as you type (off by default) shows earlier commands on the same host greyed after the cursor; Right arrow takes one. The per-host history is kept encrypted on your PC, and passwords and lines that look like secrets are never kept.
- **Keyword highlighting.** Errors and failures show in red, warnings in yellow, success in green and IP and MAC addresses in cyan and magenta, as in MobaXterm. A program's own colours win, and full-screen programs are left alone. Session > Highlight keywords turns it off and on, and your own rules in `ferossh.conf` can add more.
- **Stop following at a match.** Edit > Stop following at a match... stops the view scrolling when a line of new output matches a pattern, so a long build stops at its first error.
- **Full screen.** F11 (Settings > Full screen) covers the whole monitor with no frame or menu bar. Untick Settings > F11 switches full screen when a program on the server needs F11 itself.
- **Key bindings.** Settings > Key bindings... changes any shortcut, adds a second one, or gives one to an item that has none. Keys that would stop typing are refused, and keys that terminal programs use (Ctrl+C, Alt+B, the tmux prefix) need a yes first. Menus, the command palette and tooltips always show the current keys.

## Tools and menus

- **Tidier menus.** The Session menu is grouped into Logs and recordings, tmux, Remote desktop, Remote apps and Scripts submenus (about 14 lines instead of 38). File has one Import and export submenu, Master password sits in Settings, and Record keystrokes as script moved to Session > Scripts. Items that can't act on the focused pane are greyed out (and left out of the command palette). The [menu reference](https://github.com/jkobierczynski/FeroSSH/blob/v1.4.0/docs/guide/menus.md) lists every item.
- **Native command palette and import page.** The command palette and File > Import and export > Import connections (and Import scripts) are now native Windows pages in the tools pane, like the other tools. The palette fits the part of the pane the terminal leaves uncovered.
- **File transfer.** Click the Name, Size or Modified header to sort a list, and click again to reverse it. Del on the Local list sends files to the Recycle Bin. The right-click menu adds New folder, Rename, Permissions (`755` or `u+x`) and **Edit locally**, which opens a server file in your editor and puts it back each time you save.
- **Neutral window colours.** Settings > Window colours adds seven neutral greys, from Soft grey to Black, none tinted, each with text at 4.5:1 contrast or better. With dark menus, the Theme submenu is now drawn dark too.
- **Tools pane.** In Port forwards, Add moves with the uncovered part of the pane. Script categories fold, and the Connections tree shows each host's `user@host:port` dimmed after its name.

## Windows on ARM

- **Native ARM64 exes.** `ferossh-arm64.exe` and `ferossh-desktop-arm64.exe` run natively on Snapdragon laptops, the Surface Pro X and Windows in a VM on an Apple silicon Mac, rather than under x64 emulation. They are built, tested and checked for reproducible builds on GitHub's ARM64 runners, and signed like the x64 exes.

## Fixed

- **tmux clients that keep a window small.** tmux makes a window only as big as its smallest attached client, so a client left behind by a dropped connection, or one on another PC, could leave part of a pane empty. FeroSSH now notices, offers once to detach the other clients of that session, and Session > tmux > Detach other clients does it later.
- Renaming a session in the Session manager no longer stops after the first character.
- A login script that loops through a secret step without waiting for the host now stops, instead of typing the secret forever (found by nightly fuzzing).
- A downloaded file whose name was cut to 255 characters no longer ends in a space or dot, which Windows would drop.
- Recent connections that differ only in letter case are kept apart.

## Security

- New fuzz targets cover agent forwarding, the Mosh start-up line, remote file names and prompts, command history, and the Kerberos MIC check, next to targets for Mosh, WinRM, proxies, workspaces, the status bar and the sealed vault format.
- The vault and export files are checked against tampering (AEAD with the header as associated data), and their key derivation cost is capped so a hostile file can't exhaust memory. An imported file can't run anything: password and proxy commands in it still need your approval first.
- Command history leaves out lines that carry a secret, and the history file is encrypted with DPAPI.

## For maintainers

- The release now publishes `ferossh-arm64.exe` and `ferossh-desktop-arm64.exe` as well, and `sign-release.ps1` signs them. `wingetcreate update` can't add an installer, so this first release with ARM64 exes goes to winget with its x64 installer only. Submit the manifests that `sign-release.ps1` wrote for this release once by hand (`wingetcreate submit <folder>`); later releases send both.
- You can add the new CI job **Build and test (Windows ARM64)** to the main ruleset's required checks.
- Tag with git on your PC (`git tag v1.4.0 <merge commit> && git push origin v1.4.0`), then run `pwsh scripts/sign-release.ps1 -Tag v1.4.0` (PowerShell 7, GitHub CLI 2.93 or later).
