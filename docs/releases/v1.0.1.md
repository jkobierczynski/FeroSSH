# FeroSSH v1.0.1

*Secure connections. Forged in Rust.*

A small update to FeroSSH 1.0: the file transfer view gets a Local PC section and follows `cd` on stock Linux shells, plus a fix for imported hosts. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) introduce it.

## New

- **Local PC in the file transfer view.** Between the remote listing and the transfer queue, the side pane (Ctrl+Shift+E) now lists a folder on this PC, starting with your download folder. Tab moves into it, Enter opens a folder or uploads a file into the remote folder that's listed, U uploads the selection, and B (or a click on the title) picks another folder with the Windows folder picker. The folder you move to becomes the download folder, and finished downloads show up in the list.

## Improved

- **The file view follows `cd` without any shell setup.** Stock bash on Debian and Ubuntu never reports its directory, so "follow cd" and files dropped on a terminal always went to the home folder. FeroSSH now reads the directory from a `user@host:dir$` prompt when the shell sends nothing else, and ignores prompts from an ssh to another host inside the session. The view also follows when you switch to another pane on the same host or reopen it, and its title says "cd not reported" when the shell gives no directory at all.
- **Connections, not sessions.** The Connection manager's menus, form, prompts and command palette now say "connection" for a saved host. "Session" is kept for the sessions you have open. File names and settings are unchanged.

## Fixed

- An imported PuTTY or KiTTY session whose host was written in brackets with a single colon (such as `[name:x]`) was saved without its address. A colon is now accepted in a host only when it is an IPv6 address, so the importers, the connect prompt and the saved file agree. The fuzzer found this one.
