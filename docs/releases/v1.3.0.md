# FeroSSH v1.3.0

*Secure connections. Forged in Rust.*

FeroSSH 1.3 runs Linux programs from your servers as ordinary windows on your Windows desktop, adds copy and paste to remote and virtual desktops, and closes several ways a hostile server or desktop could cause trouble. If you're new to FeroSSH, the [1.0 release notes](https://github.com/jkobierczynski/FeroSSH/releases/tag/v1.0.0) introduce it.

## New

- **Remote apps as native windows.** Session > Remote apps > Run remote app... starts a Linux program on the pane's host and shows its windows as Windows windows, each with its own taskbar button, using [FeroStream](https://github.com/jkobierczynski/FeroStream). It runs on the pane's own SSH connection, so there is no second login, and the program keeps running on the host when you close the pane: Reattach remote app brings its windows back, from this PC or another. What the host sends is unpacked in a separate decoder process with no rights at all. The host needs Xvfb. A remote app can also be a saved connection of the new *Remote app* type.
- **The FeroStream agent in each release.** `ferostream-agent` (x86-64) and `ferostream-agent-aarch64` (64-bit ARM) are static Linux programs built from the same FeroStream code as this FeroSSH. Keep them next to `ferossh.exe` and FeroSSH copies the right one to a host that lacks it, checked by size and checksum. Copying, and removing the agent when its last program ends, can be turned on or off globally and per connection.
- **Smaller pictures for remote apps.** The host packs what it sends with palettes, LZ4 or Deflate, skips unchanged pixels and sends scrolls as copies. `RemoteAppPacking` (`auto`, `fast` or `strong`) chooses how hard it packs.
- **Clipboard for remote apps and desktops.** Session > Remote apps > Clipboard and Session > Desktop clipboard choose whether copied text goes both ways, one way or not at all, for remote apps and for RDP, VNC and virtual desktops (in the built-in viewer, Remote Desktop Connection and TigerVNC Viewer). Changes apply at once to what is already open. Text only, up to 1 MiB, and a connection's own *App clip* or *Desk clip* can only narrow the choice. Mouse selections from the host (how xterm copies) can be shared too. **Both are off until you turn them on**, because copied text can carry passwords.
- **Desktop and remote app connections open on their own.** Opening a saved desktop or remote app connection that goes through an SSH connection no longer leaves a terminal tab behind: the login runs out of sight and shows in a tab only when it needs you, for a prompt, a new host key or a failure.

## Security

- **russh 0.65.1**, with two denial-of-service fixes: a server can no longer send extension lists without limit, and channels with a zero packet size are refused.
- **The built-in VNC viewer prefers a password.** When a server offers both VNC authentication and none, the viewer now uses the password. A desktop that lets anyone in without one gets a warning on its tab, and a saved VNC connection to a machine other than its SSH server asks before it opens, since VNC is unencrypted after the SSH server.
- **Memory limits for desktops.** The built-in RDP viewer refuses oversized and compressed channel messages before IronRDP buffers them, and the window holds at most 4 MiB of a server's data waiting for a slow viewer, so neither can be made to use memory without end.
- **The built-in RDP viewer only opens desktops on the SSH host itself**, where the SSH host key already vouches for the machine. A desktop on another machine goes to Remote Desktop Connection, which checks its certificate.
- **Desktop passwords are wiped from memory after use** and never appear in debug output. Pageant support is updated to pageant 0.2.5.

## Downloads

| File | What it is |
| --- | --- |
| `ferossh.exe` | The standard client. |
| `ferossh-desktop.exe` | The same client plus a built-in RDP and VNC viewer that shows a remote desktop in a FeroSSH tab, in a sandboxed viewer process. |
| `ferostream-agent` | The FeroStream agent for 64-bit Intel and AMD Linux hosts, for remote apps. Keep it next to the exe. |
| `ferostream-agent-aarch64` | The same agent for 64-bit ARM Linux hosts, such as a Raspberry Pi. |

The exes are code signed; the Linux agents are not, but `SHA256SUMS.txt` and the build provenance cover them as well.
