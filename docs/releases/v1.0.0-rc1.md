# FeroSSH v1.0.0-rc1

*Secure connections. Forged in Rust.*

This is the release candidate for FeroSSH 1.0. It is a pre-release: everything in it is finished and tested in CI against real servers, but much of it is new since v0.1.0 and has not yet had much use on real Windows PCs. Please try it and [report what goes wrong](https://github.com/jkobierczynski/FeroSSH/issues); 1.0 follows once the problems found here are fixed.

## New since v0.1.0

**Reach more devices.**
- **Jump hosts.** `ProxyJump` (one or several hops, as `ssh -J` takes them) and `ProxyCommand` from `~/.ssh/config`, or the *Jump host* field of a saved session. Each hop logs in on its own, in a sandboxed worker of its own, and the target's connection is encrypted end to end through it.
- **Serial consoles.** Type `COM3` or `COM3:115200` at the connect prompt, or make a *Serial console* session with speed, framing and flow control. Session > Send break for ROM monitors and SysRq.
- **Telnet** for old switches, routers and console servers that offer nothing better, with a red **⚠ telnet** badge on the tab because everything goes in the clear.
- **ZMODEM (`rz`/`sz`)** over SSH or Telnet, for hosts without SFTP. Off until you turn it on in the Session menu.

**Work faster.**
- **Command palette** (Ctrl+Shift+A): one search box over every menu action, every session and every snippet.
- **Command snippets** (Ctrl+Shift+Space) and **login scripts** (`expect`, `send`, `password`, `secret`, `pause`) for devices that need answers after the login.
- **Broadcast input** (Ctrl+Shift+B) to every pane of a tab, or to every tab, with each receiving pane framed in amber.
- **Automatic reconnect.** When a connection drops (Wi-Fi switched, laptop asleep, server rebooted), the tab stays put and FeroSSH logs in again on its own for up to 15 minutes. Forwards, login scripts, tmux and SFTP transfers pick up where they were.
- **Live port forwards.** Add, edit, retry and cancel forwards on a connection that is already up, in View > Port forwards (Ctrl+Shift+P).

**Bring your sessions and passwords.**
- **Imports** from PuTTY, KiTTY, WinSCP, MobaXterm, mRemoteNG and SecureCRT, with a preview to untick what you don't want.
- **Password sources** for saved sessions: Windows Credential Manager, or 1Password, Bitwarden, KeePassXC or your own command. FeroSSH still never stores a password itself.

**Look and logs.**
- Eight fonts in View > Font, and a clearer side panel.
- Optional per-line timestamps in session logs. Every log is now sealed as it is written, with a SHA-256 hash chain beside it that shows whether it was changed afterwards.

**A stronger sandbox.**
- Each SSH connection (and each jump host) now has its own sandboxed worker, so a worker taken over by one server cannot see your other connections.
- Workers run with no Win32k system calls, Control Flow Guard, CET shadow stacks where the CPU has them, no dynamic code and a 1 GiB memory cap, and the window checks every message a worker sends. `ferossh.exe --check-sandbox | more` shows what your Windows allows. [SECURITY.md](https://github.com/jkobierczynski/FeroSSH/blob/main/SECURITY.md) describes the model and its limits.
- More fuzz targets, and a longer fuzz campaign every night.
- Fixed four crashes the fuzzer found in the terminal library FeroSSH builds on, each of which closed FeroSSH with all its tabs: a server deleting lines on screen while you were scrolled back into the history; copying a line whose last character was a wide one (Chinese, Japanese, emoji) that wrapped to the next line, which also used to copy a stray character from the line above; copying an Alt+drag block selection started on the right half of the last column; and a full-screen program redrawing while you were scrolled back, if it held its output back until the redraw was done (synchronized updates). Also fixed a freeze: searching the scrollback could hang FeroSSH on a line whose wrapped wide character had been overwritten. Inputs that once crashed a fuzz target are now kept and tried again on every change.

**Releases you can check.**
- Builds are reproducible: anyone can rebuild a release from its tag and get the same bytes.
- Each release has `BUILD-MANIFEST.json` and build provenance attestations: `gh attestation verify ferossh.exe -R jkobierczynski/FeroSSH`.
- Help > Check for updates (and an optional weekly check, off by default) reads a small update file from GitHub and checks its Ed25519 signature before trusting it. Nothing is downloaded or installed for you.
- A [user guide](https://github.com/jkobierczynski/FeroSSH/tree/main/docs/guide) covers getting started, everyday use, every setting, the security model, verifying a download and troubleshooting.

## Worth trying in this release candidate

- Switch Wi-Fi or sleep the laptop with a session open, and watch it reconnect.
- `sz somefile` on a server with ZMODEM turned on in the Session menu.
- Ctrl+Shift+A and a few letters of an action or a session.
- `ferossh.exe --check-sandbox | more`, and send the output with any sandbox problem.
- Help > Check for updates.

## Known limitations

- The exes are not code signed yet, so Windows SmartScreen and some browsers warn when you download or first run them. Check a download as described in [Verifying a download](https://github.com/jkobierczynski/FeroSSH/blob/main/docs/guide/verifying-downloads.md).
- Windows does not let the sandboxed worker reach 127.0.0.1; use `--no-sandbox` for an SSH server on the same machine.
- RSA keys work only through an agent (OpenSSH agent or Pageant), and need 3072 bits or more.
- The built-in desktop viewer has no clipboard sharing yet.
